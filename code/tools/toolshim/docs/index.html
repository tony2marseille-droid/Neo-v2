toolshim

Une couche entre ton application et Ollama. Quand un modèle ne sait pas appeler d'outils, toolshim lui apprend le format par le prompt, force une sortie JSON valide, vérifie les arguments, puis rend au client de vrais tool_calls, comme si le modèle les gérait nativement.

Démarrage

pip install -r requirements.txt
python -m toolshim --port 8330            # proxy sur http://127.0.0.1:8330
python -m unittest discover -s tests      # 15 tests
python demo_client.py --model qwen3:8b "ajoute 50 VIS-M6 au dépôt"

Dans l'agent depot, remplace l'adresse Ollama (http://127.0.0.1:11434) par celle du proxy (http://127.0.0.1:8330). Rien d'autre ne change : /v1/chat/completions (OpenAI) et /api/chat (Ollama) sont tous deux interceptés ; toutes les autres routes sont relayées telles quelles.

Ce qui se passe pour une requête

  1. RéceptionRequête chat avec tools (server.handle_chat).
  2. AiguillageModèle natif ou sans outils : relais direct. Sinon émulation (capabilities).
  3. SélectionLes 8 outils les plus pertinents sur 63 (selector).
  4. PromptCatalogue d'outils + format JSON, historique converti en texte (prompting).
  5. GénérationAppel Ollama avec schéma JSON imposé (engine).
  6. ValidationNom, arguments obligatoires, types ; si erreur, nouvelle tentative guidée (parsing).
  7. Réponsetool_calls au dialecte du client, en bloc ou en flux (formats).

Fichier config.json, surchargeable par variables d'environnement TOOLSHIM_<CHAMP> (ex. TOOLSHIM_PORT=9000, listes séparées par des virgules).

Routes

RouteComportement
POST /v1/chat/completionsInterceptée. Réponse OpenAI : tool_calls avec arguments en chaîne JSON.
POST /api/chatInterceptée. Réponse Ollama : arguments en objet.
GET /toolshim/healthÉtat du proxy et cache de détection des capacités.
toute autre routeRelayée vers Ollama sans modification (tags, embeddings, pull…).

Comportements à connaître

  • Choix des modèles. Ordre de priorité : emulated_models, native_models, détection automatique (capabilities ou template d'Ollama), émulation par défaut.
  • tool_choice. "none" retire les outils ; "required" impose au moins un appel ; {"function":{"name":…}} impose cet outil.
  • Formats tolérés en sortie du modèle. calls, tool_calls, action/parameters (format du plan d'action), JSON dans un bloc ``` ou précédé de texte, blocs <think>.
  • Corrections automatiques. Nom d'outil approchant corrigé, arguments convertis au type déclaré ("50" devient 50), arguments inconnus ignorés.
  • Échec après les tentatives. Les appels valides sont gardés ; sinon le texte brut du modèle est renvoyé comme réponse.

Limites : en émulation, le streaming est rejoué après génération complète (pas de jetons en direct) ; la fiabilité dépend du modèle, d'où l'intérêt de la sélection top-k et des tests sur tes vrais outils.

toolshim/server.py

Entrée HTTP : intercepte les chats, relaie le reste.

Relaie la requête telle quelle vers l'amont et renvoie sa réponse en flux (502 si injoignable).

Relaie si pas d'outils ou modèle natif ; sinon émule le tool calling et répond dans le dialecte du client.

Fabrique l'application (upstream et detector injectables pour les tests).

async lifespan(app: FastAPI)

Instancie amont, détecteur et moteur au démarrage ; ferme le client à l'arrêt.

async health(request: Request)GET /toolshim/health

État du proxy : amont configuré et cache de détection des capacités.

async openai_chat(request: Request)POST /v1/chat/completions

Endpoint compatible OpenAI.

Endpoint natif Ollama.

async passthrough(path: str, request: Request)ANY /{path:path}

Relais transparent de toutes les autres routes (tags, embeddings, pull…).
